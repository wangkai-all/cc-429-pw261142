# 口径不一致事件加工系统

不同来源对同一指标（请求成功率）的观测口径并不一致：

| 来源 | 观测类型 | 重试口径 | 可构造分母？ |
|---|---|---|---|
| `alpha-gateway` | full（成功+失败） | 重试**不计入**尝试 | 是 |
| `beta-pipeline` | full（成功+失败） | 重试**计入**尝试 | 是，但口径与 alpha 不同 |
| `gamma-bridge` | **只上报成功** | n/a | **否（失败不可观察）** |

系统把"接入映射 / 可比样本加工 / 报告服务"三件事独立运行，
绝不把分母口径不同的成功率直接并排排序；对不可观察的失败**不补零伪造**。

## 核心设计决策

1. **口径签名（caliber signature）**：`指标|观测类型|重试口径` 做哈希。
   签名相同才允许并排比较；alpha 与 beta 重试口径不同 → 签名不同 → 分层报告。
2. **两种可比策略，都保留比较限制**：
   - **narrow（收窄共同范围）**：只在所有相容来源共同观察到的单元比较，其余单元进 `exclusions` 留痕。
   - **stratified（分层）**：按签名分层，层内取共同范围；跨层永不并排。
3. **success-only 来源**：裁决为 `SUCCESS_ONLY_NO_DENOMINATOR`，只报成功量，
   成功率 `rate=null`（页面显示"不可计算"），**不补零**。
4. **被排除/被拒绝记录全部保留**：坏记录、口径冲突、未映射来源、范围外单元、
   静默单元都带原因码落 `retained_records` / `exclusions`，可在网页追溯，不静默丢弃。
5. **只追加版本**：口径映射版与输入版都是快照、只追加、不改写；
   作业冻结自己的映射版，旧报告永远可沿旧映射复现。来源补字段后可生成新可比版。
6. **断点恢复**：加工分 7 个阶段、每阶段写 checkpoint；中断后用**同一输入版 + 冻结映射版**
   恢复，已完成阶段跳过（幂等，排除账不翻倍）。

## 目录结构

```
src/app/
  models.py      口径常量、签名、原因码、时间/单元工具
  store.py       SQLite 持久化（版本快照、检查点、事件、留痕、报告）
  mapping.py     映射校验与版本化（非法修改整体拒绝，不产生半截版本）
  ingest.py      输入快照 + 规范化（坏记录进 retained_records）
  sample_data.py 三个来源的虚构原始事件（真实加工数据，非零填充）
  pipeline.py    7 阶段加工管线、相容性裁决、范围/分层、指标、报告、跨版比较、恢复
  services.py    服务层（网页与 CLI 共用）
  server.py      标准库 HTTP：JSON API + 静态网页，启动自动恢复中断作业
  cli.py         命令行（demo/serve/ingest/mapping/resume/report/...）
src/web/         单页前端（无第三方依赖，纯 SVG/HTML 图表 + 表格兜底）
tests/           10 个端到端测试
```

## 运行

无第三方依赖，Python 3.11 标准库即可。

```bash
# 端到端演示：中断 → 恢复 → 补交 → 改口径补字段 → 新可比版
python3 src/app/cli.py demo

# 启动网页（默认 127.0.0.1:8080）
python3 src/app/cli.py serve --port 8080

# 测试
python3 -m unittest discover -s tests -v
```

## 网页能做什么

- **摄入与加工**：一键跑样例、自定义 JSON 摄入、可勾选"注入中断"并一键恢复，查看每作业检查点。
- **口径映射**：在线编辑映射 JSON，整体校验通过才生成新版本并激活；查看历史版本与签名。
- **不相容与排除留痕**：按作业查看来源裁决原因、被保留的坏/冲突记录原文、被排除单元与原因码。
- **报告与比较**：narrow / stratified 切换，成功率条形图（不可计算来源不入图、仅标成功量），
  明细表兜底，以及两个输入版之间的跨版比较（口径变化给 `CALIBER_CHANGED` 警告，不强行比较）。

## 数据真实性说明

虚构事件由 `sample_data.py` 实际生成，包含成功、失败、重试、来源静默单元和 1 条坏记录。
gamma 在 U3 初始完全无事件（不造零）；补交后只增加它真实上报的成功事件；
升级 full 口径时才携带真实失败事件。任何阶段都没有用零值填充缺失的失败/分母。
